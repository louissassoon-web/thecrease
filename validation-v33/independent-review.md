# Independent review of the revision 33 canvas code

Run on 30 and 31 October 2026 against the design canvas build (sha256 0220bdbf…), before the handover fixes. Four review lenses (correctness, lifecycle and platform, repository rules, accessibility and copy), duplicates merged, then three independent checkers per finding (code, reproduce, scope); a finding stands when at least two do not refute it. Line numbers refer to that canvas build, not to the committed sources. Written by the review's synthesis agent; the handover notes in PROJECT_NOTES.md say what was done about each.

## Verdict

Blocker
None.

Should-fix
1. Platform.storage.get takes a hook's null as an answer, so a fresh career can overwrite the real save
Where: R33 dist/index.html 2669 (Platform.storage.get); load path 2719; dated-backup loop 2720; APP_STORE_READINESS.md 35 and 49.
Why: a shell whose get returns null for an unknown key (Capacitor Preferences, any getItem-style wrapper) hides a career still held in localStorage, the setup dialog opens as a first visit and the next persist() overwrites the real save without the dated-backup path ever running, because nothing threw.
Fix: `if(v!==undefined&&v!==null)return v;` and state in the contract that a miss is undefined or null and falls through to localStorage. Already in HEAD (src/ui.js 20, notes line 15).

2. Hardware back exits the app from cancellable confirmations and during simulation
Where: R33 3311 (Platform.on('back')); restartDialog markup 747, confirmDialog 752; simulateInnings 2866-2868; pauseSimBtn 3292; Escape handler 3294.
Why: the shell contract is `if(!back.detail.handled) App.exitApp()`, so an Android player pressing back on "Restart entire game?", "Declare this innings?" or a running Simulate innings is sent to the launcher instead of cancelling or pausing, while Escape closes the same two dialogs.
Fix: drop restartDialog and confirmDialog from `blocking`, send restartDialog to its Keep playing path (`restartKind=null;openDialog('settingsDialog')`), let confirmDialog fall through to closeDialogs(), and replace the simulating branch with `paused=true;state.watchUntil=0` keeping handled=true. Already in HEAD (src/ui.js 672).

3. Service worker never detects a changed index.html
Where: dist/sw.js 8-10, shell(); registered from Platform.offline (R33 2690), message listener 2689.
Why: shell() returns `cached` to the navigation and only afterwards calls `cached.clone().text()` in the refresh, which throws "Response body is already used" into `.catch(()=>null)`, so the no-bump refresh the notes promise never stores or announces a new build and only a VERSION bump delivers an update.
Fix: read the old text before handing the response over (`cached=await cache.match(key),old=cached?await cached.clone().text():null;` then `return cached`), or re-run cache.match inside the refresh. HEAD restructures this into a separate check() that fetches INDEX (dist/sw.js 11-13).

4. Service worker answers every same-origin navigation with the cached game and compares that page against the cache entry
Where: dist/sw.js 15 (fetch condition) and 8-10 (fixed key './index.html', fetch of e.request.url, cache.put); consumer R33 2689.
Why: any navigation in the root scope (/privacy.html, /sw.js, a 404) is served the game, and the fetched page is compared with and stored over ./index.html with an "Update ready" prompt; only the clone failure in finding 3 masks the overwrite today, and the uncached path (old===null) is not masked at all.
Fix: `INDEX=new URL('./index.html',self.location.href).pathname, ROOT=INDEX.slice(0,-'index.html'.length)`, route only `url.pathname===INDEX||url.pathname===ROOT` to shell(), and fetch INDEX there, never e.request.url. Already in HEAD (dist/sw.js 5, 19, 23).

5. Sound preference bypasses Platform.storage
Where: R33 3167 and 3171 (Sound module); APP_STORE_READINESS.md 15 and 49.
Why: these are the only UI storage calls left on raw localStorage, so a mute never reaches the native mirror and a shell that hydrates or answers reads brings sound back after an eviction, contrary to "All UI storage goes through Platform.storage" and the key list.
Fix: `Platform.storage.get('cricket.sound')` and `Platform.storage.set('cricket.sound',enabled?'on':'off')` (Platform is defined at 2661, in scope). HEAD documents the exception instead (notes line 15, "hydrated but not mirrored"); the two-token change removes the only exception to the contract and is the better end state.

6. Hydration key list names a key that does not exist and omits two that do
Where: APP_STORE_READINESS.md 49; R33 2720 and 2723 (recoveryKey), 2844 and 3302 (cricket.before-import).
Why: a shell that hydrates exactly the documented keys restores the dated backup but not `cricket.career.v5.recoveryKey`, so recoveryRecord is null and the player loses the in-app route to the original save, the one case the recovery dialog exists for; `cricket.timing*` matches nothing.
Fix: add `cricket.career.v5.recoveryKey` and `cricket.before-import`, drop `cricket.timing*`. Already in HEAD (notes line 49).

7. Service worker gate admits http, so it registers on the localhost:8000 dev server
Where: R33 2686 (Platform.offline); APP_STORE_READINESS.md 18; package.json serve and frames.
Why: `/^https?:$/` lets http through and localhost is a secure context, so `npm run serve` registers the worker with scope `/`, manual play shows the previous build cache-first after a rebuild, and any other project later served on port 8000 is answered with the cached cricket page until the worker is unregistered, while the notes claim https-only.
Fix: `protocol!=='https:'` in the gate (keep the file: message branch), which excludes plain-http localhost without a hostname test, plus a line in the notes that dev servers never register. HEAD kept localhost registration and corrected the notes and README-DEV instead, which is consistent; tighten only if local worker testing is not wanted.

8. Install button stays live after a dismissed prompt but the saved event can only be prompted once
Where: R33 2695 (Platform.install), 3314 (installBtn click), 3316 (callback).
Why: after the player dismisses the install sheet the button remains and every further tap is a rejected promise nothing reads, until the browser happens to re-fire beforeinstallprompt, which not every Chrome does in the same page session.
Fix: consume the handle on use: `const p=installPrompt;installPrompt=null;$('installBtn').hidden=true;p?.();`; a later beforeinstallprompt re-shows the button through onPrompt. Already in HEAD (src/ui.js 675).

9. Graphics select aria-label hides the help text from assistive technology
Where: R33 markup 188 (#graphicsSelect); renderSettings 2826.
Why: aria-label wins over `<label for>` in accessible-name computation, so screen readers hear only "Graphics quality" and never the help text or the live "Drawing at N× resolution" line, unlike the Haptics row beside it.
Fix: add `aria-describedby="graphicsHelp"` to #graphicsSelect (keeping a short name), or drop the aria-label. Already in HEAD (src/markup.html).

10. Sharp help text says "Full resolution" but the code caps Sharp at 2x
Where: renderSettings R33 2826; renderScale 2704.
Why: on a 3x phone the row reads "Full resolution. Uses more battery on large screens. Drawing at 2× resolution.", which contradicts itself and the code.
Fix: 'Sharpest drawing, up to 2×. Uses more battery on large screens.' Already in HEAD (src/ui.js renderSettings).

Nit
11. exportRecovery reports success regardless of saveFile's result
Where: R33 3327 (exportRecovery); compare the export button at 3301.
Why: it discards the boolean saveFile returns for exactly this purpose and always writes "Original save exported", so a declined shell hook plus a throwing Blob fallback tells the player a lost save was exported, in the one dialog where that matters.
Fix: `const ok=Platform.saveFile(name,recoveryRecord.raw);` and branch the message on ok as the export button does. Already in HEAD (src/ui.js 688).

12. Haptics help text omits the bowling-release pulse and says "browser" inside a native shell
Where: R33 188 (#hapticsHelp), renderSettings 2826, releaseBowling 3246, finishBall 2854.
Why: releaseBowling pulses on the player's bowling release and the contact pulse is batting-only, so the copy misdescribes the feature, and 'Not available in this browser.' is chosen on availability alone, so it appears inside a Capacitor build with no haptics hook.
Fix: 'Short pulses at your bat contact and bowling release; stronger patterns for boundaries and wickets.' and 'Not available on this device.' in both the markup default and renderSettings. Already in HEAD.

13. Install copy is phone-only but the controls also appear on desktop Chromium
Where: R33 186 (#installBtn), ready() 2688, Platform.install callback 3316.
Why: beforeinstallprompt fires on desktop Chrome and Edge and ready() runs on any top-level https page, so a desktop player (a surface the @media(min-width:700px) rules support) sees "Install on this phone" and "Add it to your home screen".
Fix: 'Install this game' for the button and 'Ready to play offline. Install it for an app-style window.' for the status line. HEAD renamed the button (src/markup.html) but the status line (src/ui.js 41) and the notes' mention of the old button text (line 18) remain.

## Refuted claims

APP_STORE_READINESS.md line 53 and the hydration paragraph above it say the mirror exists because WebView localStorage can be evicted and that the shell should "mirror every set", so under quota pressure the native copy stops at the last successful localStorage write exactly as the claim describes; the proposed fix (mirror regardless, then rethrow) preserves persist()'s reporting and is sound.
  - reproduce: Tracing the only realistic throw (the origin's own quota, filled by the app's cricket.career.v5, backup and before-import keys): when localStorage.setItem throws at 2670 the previous value stays in place, so the hot copy and the Preferences mirror both hold the last save that succeeded, persist() at 2716 sets saveOK=false and shows "Use Export to save" on every ball and in the pause menu (2823), and a relaunch after eviction hydrates from the mirror exactly the same save that a relaunch without eviction loads from localStorage via get() at 2669, which is the documented contract (notes line 15 and the comment above 2667: localStorage remains the hot copy, set() still throws when the device is full and persist() reports it). The claim reaches a "wrong" outcome only by redefining the mirror as an overflow store that accepts writes the hot copy rejected, a design change rather than a defect; the proposed fix would make the mirror diverge from localStorage while persist() keeps telling the player the save failed, so get() at 2669 would later load a save the player was told was never written.
  - scope: R33 line 2670 `set(key,value){localStorage.setItem(key,value);try{hooks.storage?.set?.(key,value);}catch{}}` does skip the mirror when setItem throws, but R32 had no mirror at all (persist at R32 2645 `localStorage.setItem(STORAGE,...)` with the identical `catch{saveOK=false;...'Use Export to save'}`, backup write 2649, before-import 3229 all unchanged apart from the Platform indirection), so under the same quota failure R32 keeps nothing while R33 keeps the last accepted save and also requests `navigator.storage.persist()` (`Platform.keep()`, 3283): the change adds a partial safety net and regresses nothing.
